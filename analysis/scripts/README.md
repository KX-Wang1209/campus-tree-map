# 数字校园地图 —— 数据获取与底图生成

天津滨海职业学院（本部/北校区，塘沽庐山道 1101 号）数字校园地图项目的基础数据模块。

本模块解决一个问题：**做这个地图，底图数据从哪来、够不够用、树的数据有没有。**

## 结论摘要

| 数据 | 来源 | 状态 |
|---|---|---|
| 校园边界 | OpenStreetMap | 有，31 顶点多边形，贴合实际围墙 |
| 建筑轮廓 | OpenStreetMap | 有，26 栋，与卫星影像逐栋核对贴合良好 |
| 建筑高度/层数 | — | **无**，OSM 无 height/levels 标签，需按类型估算 |
| 道路、球场、水体、绿地 | OpenStreetMap | 有 |
| 卫星影像 | Esri World Imagery | 有，2025-05-20 拍摄，原生 0.34 m/px |
| **树木** | — | **完全没有**，OSM 记录数 = 0 |

## 运行方式

```bash
# 1. 拉取 OSM 矢量数据（需要联网）
python analysis/scripts/fetch_osm_campus.py

# 2. 生成建筑体块高度估算与底图（需要联网下载影像瓦片）
python analysis/scripts/build_campus_3d.py
```

依赖：`requests`、`Pillow`。Python 3.10+。

## 输入

无本地输入。数据从两个在线服务获取：

- **Overpass API**（OpenStreetMap 数据查询），按 `BBOX = (39.0628, 117.6290, 39.0719, 117.6440)`
  查询，即校园外扩约 100 m 的范围
- **Esri World Imagery** 瓦片服务，z18（该区域原生分辨率上限）

## 输出

| 文件 | 内容 |
|---|---|
| `data/raw/osm/campus_boundary.geojson` | 校园边界多边形 |
| `data/raw/osm/campus_osm_features.geojson` | 130 个要素（边界内 69 个），带 `in_campus` 字段 |
| `data/processed/campus_buildings_3d.geojson` | 26 栋建筑，带估算高度（WGS84，供三维使用） |
| `data/processed/campus_buildings_3d.csv` | 同上，表格形式 |
| `figures/campus_basemap.png` | 校园卫星底图 + 建筑轮廓 + 边界 |

## 结果关键参数

**影响结果、需要记住的参数：**

- `NATIVE_Z = 18`（`build_campus_3d.py`）
  Esri 影像在本地块的元数据为 `RESOLUTION 0.34 m`、`MaxMapLevel 18`。
  **z18 已是原生分辨率上限，用 z19 属于插值放大**，会让人误以为精度更高。
  做树冠核验时两者都试过：z19 插值图报 499 个候选，z18 原生图报 426 个，
  说明插值会高估树冠数量。

- `DEFAULT_STOREY_H = 3.2`、`DORM_STOREYS = 6`、`TEACH_STOREYS = 5`、`DEFAULT_STOREYS = 4`
  建筑高度估算参数，单位为米/层。**26 栋建筑的高度全部为估算值**，
  每栋在输出里都有 `height_basis` 字段标明依据。
  要精确高度需向学校基建处索取图纸。

- `BBOX`（`fetch_osm_campus.py`）
  查询范围。若要做新校区（黄港区域），此参数需要替换。

## 已知问题与限制

1. **树木数据为零**——这是本项目最核心的约束。节目详见
   `results/reports/数字滨海学院_可行性调研报告.md` 第 2.4 节。
   已实测过从卫星影像自动提取树冠（ExG 植被指数 + 连通域分析）：
   施工区绿色防尘网造成大量误报，密集树丛会粘连成单块造成漏报，
   **不能直接当数据用，只能作为人工核对的底稿**。

2. **建筑高度是估算的**。OSM 在本校区没有任何 `height` 或 `building:levels`
   标签，26 栋建筑全部按建筑类型套用默认层数。

3. **坐标系**。输出为 WGS-84（EPSG:4326）。接入高德（GCJ-02）或
   百度（BD-09）底图时必须做坐标转换，否则会有几十米偏移。

4. **影像时效**。见下一节——这不是"用了旧图"，2025-05-20 已是该区域可用的最新影像。

## 底图为什么是 2025-05-20（已核实，别再换源试探）

有人会问"为什么不用更新的影像"。查证结论：**2025-05-20 就是这块地能拿到的
最新一版，不是我们挑的旧图。**

核实方法：把当前 Esri World Imagery 与 Wayback 历史版本的同一瓦片逐像素比对
（z18，校园中心）：

| 版本（发布日期） | 与当前底图的像素差 | 结论 |
|---|---|---|
| 2026-08-05 | 0.00 | 完全相同 |
| 2026-06-30 | 0.00 | 完全相同 |
| 2026-02-26 | 0.00 | 完全相同 |
| 2023-08-31 | 27.25 | 是更早的另一张 |

也就是说，2026 年三次新发布都没有覆盖这块地，用的仍是 2025-05-20 拍摄的影像。
Esri 元数据里它的编号是 `DYNAMIC_ESRI_Tianjin_25Q4`、分辨率 0.34 m。

**国内源（高德）确实更新，但不适合这个项目。** 实测对比：

- 高德影像的施工进度明显更晚（新楼已封顶、屋面已清理，Esri 那张还盖着防尘网），
  说明拍摄时间更近
- 但高德这张 **几乎看不到树冠**：绿色占比 28%（Esri 是 50%），
  植被像元平均亮度 51（Esri 是 71），树呈暗色小点
- 推测是落叶季（秋冬）拍摄 —— 天津的落叶乔木在冬季没有树冠

**对一个"数树、标树"的项目来说，"能看清树"比"楼更新"重要得多。**
所以底图仍用 Esri 的 2025-05-20。

实测对比图见 `figures/底图来源对比.png`。

另一个技术限制：高德影像 z19 及以上返回灰底占位图（"此区域无卫星图"），
原生最高只有 z18，放大了也不会更清楚；Esri 在同一区域 z18 就是原生分辨率上限。

## 数据来源与许可

- OpenStreetMap：ODbL 1.0，使用时需署名
- Esri World Imagery：仅供本次可行性调研评估使用，
  **正式项目上线需替换为高德/百度的开放平台 API**（见报告第六节）
