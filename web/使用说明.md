# 校园植物地图 —— 使用说明

学生带着手机在校园里边走边记录。有两种用法，按需要选：

| 用法 | 适合场景 | 特点 |
|---|---|---|
| **协作模式**（推荐） | 分几组学生同时记录 | 谁记了什么，别人手机上自动出现，**不用收文件再合并** |
| 本地模式 | 没网、或只是自己试用 | 数据存在手机里，靠导出文件汇总 |

两种模式用的是同一个网页，**会自动判断**：连得上服务器就是协作模式，
连不上就退回本地模式，都不会丢数据。

---

## 最省事的用法：双击打开

`dist/` 目录里有两个压缩包，按电脑系统选一个：

| 文件 | 给谁用 |
|---|---|
| `校园树木地图-macOS.zip` | Mac 电脑 |
| `校园树木地图-Windows.zip` | Windows 电脑 |

**解压后双击里面的「校园树木地图」就行，不用装 Python，也不用敲任何命令。**

打开后会自动弹出浏览器，页面底部会显示一个地址：

```
🟢 实时协作中 · 点地图添加第一棵树 · 📱 http://192.168.1.103:8080/
```

**点一下那个 `📱` 开头的地址就能复制**，发到班级群里，
学生用手机浏览器打开就能记录。

### 第一次打开可能被系统拦

两个系统都会对"没花钱买数字签名"的程序提个醒，不是病毒：

- **macOS**：提示"无法打开，因为 Apple 无法检查它是否包含恶意软件"。
  解决：**在「应用程序」里找到它，按住 Control 键点一下图标，选「打开」**，
  再点一次「打开」。以后就不用这样了。
  （或者：系统设置 → 隐私与安全性 → 下方点「仍要打开」）

- **Windows**：提示"Windows 已保护你的电脑"。
  解决：点「更多信息」→「仍要运行」。只需设置一次。

### 数据存在哪

电脑的**「文档」文件夹**里，名叫 `CampusTreeMap`：

```
文档/CampusTreeMap/trees.json     所有记录
文档/CampusTreeMap/photos/        照片
```

想备份就整个文件夹复制走；想重新开始就删掉它。
**数据不在应用里面**，所以应用删了数据也还在。

### 怎么关闭

- macOS：右键点 Dock 里的图标 →「退出」
- Windows：关掉那个黑色的命令行窗口

### 自己重新打包

如果改了网页内容（比如加了新物种），重新生成应用：

```bash
sh launcher/build.sh
```

需要 Go 工具链。脚本会一次生成 macOS 和 Windows 两个版本。

---

## 另一种用法：用 Python 起服务

电脑上装了 Python 的话，也可以不打包直接用：

```bash
python3 web/server.py
```

效果和打包版一样，只是需要电脑里有 Python。

## 本地模式：不用服务器

双击 `web/index.html` **不行**（浏览器安全限制，读不了数据文件），
需要起个静态服务：

```bash
cd web
python3 -m http.server 8899
```

然后访问 <http://127.0.0.1:8899/>。

**手机上怎么用**：电脑和手机连同一个 WiFi，手机浏览器打开
`http://<电脑的局域网IP>:8899/`。电脑 IP 用 `ipconfig getifaddr en0`（Mac）
或者 `ipconfig`（Windows）查。

这个模式下学生各记各的，最后靠导出文件汇总——**具体做法见下面「多人一起记录」一节**。

## 给做记录的同学

**基本流程是"走到树旁边再点"，不要对着几十米外的树估位置。**

1. **站到植物旁边**，等地图上的蓝点稳定下来（手机定位会有几米漂移，等一下会更准）。
2. 点底部 **「＋ 记录身边的植物」** —— 会用你当前位置。
3. **选种类**。按学校自己发的《校园植物名录》分成四类：
   **乔木（37 种）、灌木或藤木（24 种）、草本（3 种）、竹类（1 种）**。
   名录太长，面板默认只展开「乔木」，其他三类点标题就展开。
   赶时间可以直接在上面搜索框打名字，比如输入"银杏"。
4. **名录里没有怎么办** —— 每类末尾都有一个 **「其他」**，
   选了之后在下面的输入框里写清是什么就行。**叫不准学名就写本地叫法。**
5. **完全认不出来就点「暂不确定」**，先记位置，回头查了再补。
   **位置比种名重要**——名字可以后补，位置补不了。
6. **照着表格填就行，不同类别填的东西不一样**（表格会自己变，不用你选）：

   | 类别 | 要填的 |
   |---|---|
   | 乔木 | 胸径、树高、**株数** |
   | 灌木或藤木 | **株数** |
   | 草本 | **面积**（平方米） |
   | 竹类 | **丛数** |

   树高拿不准就估个数；胸径是离地 1.3 米处的树干粗细，
   有卷尺就量，没有就跳过——这两个都是选填。
7. **拍张照片**。照片是最有用的证据，尤其对认定种类有帮助。
8. 备注里写点只有现场才知道的：靠哪栋楼、有没有长椅、有没有刻字。

**几个实用提示**

- **成片同种的可以合并成一条**（比如一排行道树、一片绿篱），
  填总量，不用一棵一棵点。
- **数不清就点「若干」**（在数量右边）。
  这是给那种"一整片绿篱""一丛竹子"准备的——数不出具体多少，
  硬编一个数字反而是假数据。草本那栏对应的是 **「未测」**。
  标了之后统计时不会并进总数，会单独注明"另有 N 处若干"，汇报时不会被误读。
- 记录会**立刻存到手机本地**，关掉网页、断网都不会丢。
- **完全没有信号也能用**，底图和物种表都存在页面里了。

**关于单位**：株、丛、平方米是三种不同的量，
统计时**分开算**，不会加在一起（加出来的数没有意义）。

## 给演示/汇报的人

- **「统计」** 看各类构成和总量，条形图按类别分组，汇报时直接截屏就行。
- **「清单」** 可以搜索、排序，导出 CSV 交给老师（Excel 直接打开，中文不会乱码）。
- **要长期保存就用「备份 JSON」**，它包含照片，可以再导回来。

⚠️ **数据存在浏览器里**，换台电脑或换个浏览器就看不到了。
重要数据一定记得导出备份。

## 关于数据

| 内容 | 来源 |
|---|---|
| 底图影像 | Esri World Imagery，2025-05-20 拍摄，0.34 米分辨率 |
| 建筑轮廓 | OpenStreetMap（ODbL 许可，使用时需署名） |
| 物种库 | 学校《校园植物名录（26年10月）》，共 65 种 |
| 记录数据 | 师生实地记录，保存在各自浏览器本地 |

**两个要知道的局限**

1. 底图是 **2025 年 5 月**拍的，校园西南角当时还在施工，现在的情况可能不一样。
2. 建筑高度是**按楼层估算**的（OSM 里没有真实高度数据），
   鼠标悬停在建筑上会显示高度和它的推算依据。

## 多人一起记录，数据怎么合到一起

### 用协作模式：什么都不用做

各组学生记录的数据**实时汇总在同一台电脑上**，不用导文件、不用手工合并。
演示的时候打开大屏刷新一下，就能看到所有小组记的树。

一个人删掉某条记录，其他人的地图上也会同步消失。

> 服务器万一崩了或者关了，学生**照样能继续记录**——数据先存在手机上，
> 服务器恢复后自动补传上去。所以不用担心白记。

### 用本地模式：靠导出文件汇总

如果没用服务器，就按下面的办法手动汇总：

1. **每人各记各的**。学生在自己手机上记录，数据存在各自手机里，互相不影响。
2. **各自导出**。在「清单」里点「备份 JSON」（带照片）或「导出 CSV」（不带照片）。
   文件名会自动带上记录人和时间，比如 `校园树木备份_张三_20261004_1809.json`，
   **交上来不会互相覆盖**。
3. **一个人负责汇总**。打开「清单」→「导入」，选别人的文件。
   可以一个一个导，也可以连续导多个文件。

### 导入时会自动查重

如果别人记的和你已有的记录**离得很近（15 米内）、类别相同、种名也相同**，
系统会弹出一个确认框，把两条记录并排摆出来让你看：

- **合并** —— 认定是同一处。数量取大的（面积也取大的），备注拼起来，
  照片加起来（最多留 3 张），记录人变成 `张三+李四` 这样的形式。
- **都保留** —— 认定是紧挨着的两处不同的植物。
- **丢弃导入** —— 认定自己这条更准，不要别人那条。

**类别不同就一定不算重复**——乔木和草本长在同一个位置，那是两种东西。

**默认选项看情况**：一般默认「合并」；但如果两条记录的**大小差得明显**
（树高差 1.8 倍以上、或胸径差 1.6 倍以上，比如一株 3 米小苗挨着一株 9 米大树），
就默认「都保留」——因为这种一大一小的组合，更可能是两株而不是同一株被记了两次。
这种条目标题上会标出「大小差得明显」。

反过来，两个人各估一次同一棵树（比如一个估 8 米一个估 12 米），
**不会**被当成两株——目测树高本来误差就大，1.5 倍以内是正常范围。

如果一次导入发现好几处，可以逐个决定，也可以点「全部合并」一键处理。

**为什么是 15 米**：手机 GPS 在校园里通常有 5～15 米误差，同一棵树两个人测，
位置会差几米。这个半径就是用来容忍这个误差的。但它只是**提示**，不会自动合并——
最终由人判断，因为也有可能真是两棵挨着的树。

### 两株树挨得很近怎么记

**站在那儿正常记就行，不用先挪开。**

地图上的树标记看着是个小圆点，但它的**点击范围有好几十米**。所以以前会有个坑：
想在大树旁边记一株小苗，一戳就打开了那棵大树的记录，加不了新的。

现在不会了——只要你处在「正在选点」的状态（刚点完「＋ 记录身边的树」），
点到标记就是**在这个位置记一株新的**，而且用的是你**实际点的那个位置**，
不是标记中心。这样差的那几米正好能把两株分开。

### 几个要注意的

- **两种模式可以混用**。有人在服务器上记，有人离线记完再导入，都能合到一起。
- **CSV 也能导回来**。如果同学只交了 CSV（没照片），同样能合并。
  但 CSV 里没有照片，想要照片得用 JSON 备份。
- **同一个文件重复导入不会重复**，系统会认出来并跳过。
- **万一两个人的记录编号撞了**（概率极低），服务器会靠位置判断：
  位置不同就当成两条都留着，换个编号存，**不会悄悄丢掉一条**。
- **照片不会在合并时丢失**，会去重后保留，每条记录最多 3 张。

## 平面 / 三维 切换

页面右上角有个 **「平面 / 三维」** 切换按钮，两套视图共用同一份数据——
在平面图里记的树，切到三维立刻就能看到，反过来也一样。

**三维视图能看到什么**

- **建筑按真实层数立起来**：26 栋楼按各自的高度挤出成体块，
  点一下建筑会显示它的高度和推算依据
- **植物按种类着色**：点一下会弹出名称、数量（草本显示面积）、记录人
- **体量按类别区分**：乔木按实测树高定大小，灌木和竹丛画得矮一些，
  一眼能看出是草是树
- **可以旋转和倾斜**：拖动旋转视角，右键（或双指）调整俯仰角，
  从侧面看能看出哪栋楼高、哪棵在哪栋楼旁边

**三维适合什么时候用**：汇报展示、看空间关系（比如"这棵银杏在哪栋楼前面"）。
**平面适合什么时候用**：实地记录（看得清地面细节，操作更快）。

### 三维专用的两个小工具

右上角除了「平面 / 三维」，三维模式下还会多出两个按钮：

**🔄 环绕** —— 相机自动绕着校园慢慢转一圈（约 100 秒转完）。
汇报时不用手拖，画面自己动，适合投在大屏上放。
如果当前视角太平，它会先自动抬高一点，让建筑立体感更明显。
再点一下停止。

**🔍 筛选** —— 按种类筛选。列出当前数据里有的种类（带颜色和数量），
勾掉不想看的，**没选中的会变暗变小，但仍然看得见**——
这样既能突出想看的种类，又不至于丢掉"这一片整体有多少"的信息。
点「全选」一键恢复。

筛选状态会**记住**：切到平面记完再切回来，筛选还在。

> 为什么不做成"直接隐藏"：实地看的时候，剩下的树如果全都消失，
> 容易误以为那片区域没记录。变暗保留能避免这种误判。

**关于高度数据的说明**

建筑高度不是实测的，是按楼层数估算的（OSM 里没有真实高度）。
9 栋学生公寓按 6 层、教学实训楼按 5 层、层高 3.2 米推算。
**鼠标点建筑能看到它用的是哪个依据**，不是猜的。

植物的"立体感"是按树高算的：有实测树高就用实测值，
没测的按默认值（灌木和竹丛画得矮一些）。
所以视觉大小只反映记录信息，不是真实冠幅。

**技术要求**：三维视图需要浏览器支持 WebGL（近几年的手机和电脑都支持）。
如果打不开三维，平面视图不受影响，照常能用。

## 技术说明（给要改代码的人）

纯粹的前端静态页面，不需要后台、不需要数据库。

```
web/
├── index.html          页面结构
├── app.css             样式
├── app.js              平面视图逻辑 + 数据管理
├── view3d.js           三维视图逻辑（MapLibre GL）
├── server.py           协作服务器（只用 Python 标准库）
├── campus.json         校园矢量数据（建筑/道路/场地/水体/边界）
├── species.json        物种库
├── bounds.json         地图范围
├── tiles/              离线地图瓦片 z17-z19，共 546 张
└── vendor/             Leaflet + MapLibre GL（已本地化）
```

**为什么把瓦片和渲染库都放在本地**：学生在校园里用，
不能假设有稳定的网络。现在整个应用零外部依赖。

**两个渲染库并存是有意的**：
- Leaflet 做平面视图——轻快、地面细节清楚、手机上操作跟手
- MapLibre GL 做三维——WebGL 渲染，能挤出建筑体块

两者共用一个 `state.trees`，切换视图时互相同步，不存在两份数据。

**MapLibre 的一个坑（踩了很久，务必注意）**：

**不要在三维视图里用 `symbol` 文字图层。** symbol 图层要加载远程字体
（`text-font` / `glyphs`），字体拉不到的时候，它会把**整个数据源的渲染一起卡住**
——表现为同源的圆点图层也一个都不显示。数据、图层、可见性全都正常，
`queryRenderedFeatures` 恒为 0，非常难查。

所以数量的标记改用「加粗描边」表达，不用文字。
如果以后要加文字标注，得先把字体文件也下载到本地 `vendor/` 里自托管。

**四类各自的字段**定义在 `app.js` 顶部的 `CATEGORY` 表里。
要改"某一类记什么"，改那张表就行（表单、统计、CSV 导出都跟着变）。

**另一个教训**：`queryRenderedFeatures` 只统计**当前屏幕范围内**的要素。
用它判断"渲染有没有问题"时，必须先确认要素在视野内、且瓦片已经渲染完，
否则很容易误判成代码有 bug。

**数据存哪**：本地模式存浏览器 `localStorage`（key `tjbpi_trees_v1`）；
协作模式下由 `server.py` 存在 `data/live/`。

**要重新生成数据**（换底图、改物种库、加新校区）：

```bash
python analysis/scripts/build_web_assets.py
```

## 已知的可改进点

- 建筑高度是估算的。要准确得找学校基建处要图纸。
- 物种分类和名称来自学校发的《校园植物名录》，已经逐项核对过。
  实地走一圈后如果要增删，改 `analysis/scripts/build_web_assets.py`
  里的 `SPECIES` 再重新生成即可。
- 南侧那栋 220 米长的楼，规划图上西边是**物流系**、东边是**经管系**。
  OSM 只给了整体轮廓，所以按经度切成两段分别命名（各 110 米）。
  这个分界点和位置**已请学校老师确认过**。要调整就改
  `SPLIT_BY_LON` 里的经度。
- **「二报」目前是个悬空的点位**，不是建筑轮廓——2025 年 5 月的影像上
  还没建成（位置已确认）。等建成后可以补上真实轮廓。
- 如果校园面积大、记录点多，瓦片可以按需追加密级。
